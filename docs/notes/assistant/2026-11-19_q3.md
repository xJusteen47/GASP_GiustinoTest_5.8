## Come GASP gestisce il ritorno in idle (secondo la documentazione)

La documentazione di GASP **non descrive** un sistema dedicato di "stance recovery" a passi dopo un montage. I meccanismi documentati che entrano in gioco sono quattro:

1. **Motion Matching con pose matching dei piedi.** Lo schema include un **Pose Channel** sui piedi (`foot_l`/`foot_r`, flag **Position**/**Velocity**). La query usa la posa raccolta dal **Pose History** node, che fotografa la posa *nel punto del grafo in cui si trova*. Il database idle viene scelto da `Update_MotionMatching` tramite `CHT_PoseSearchDatabases`, e il blend dipende da `Get_MMBlendTime` e da `Get_MMInterruptMode`. L'idea è che MM scelga un frame con i piedi vicini alla posa attuale, invece di imporre una stance fissa.
2. **Foot Placement** (dalla 5.5). Il plant si basa sulle curve di velocità dei piedi (foot speed L/R, generate con l'anim modifier). Le **Plant Settings** stanno in una variabile, perché in GASP servono valori diversi in movimento e in arresto. Il nodo ricalibra anche il bacino verso il punto medio dei piedi.
3. **Offset Root Bone.** `Get_OffsetRootTranslationMode` e `Get_OffsetRootRotationMode` mettono la modalità **Release** quando c'è un montage nel Default Slot o quando il personaggio è fermo. I known issue citano esplicitamente che *"release + motion warping nel montage può causare movimenti indesiderati"*.
4. **Continuing pose bias e block transition notify** per non abbandonare l'animazione corrente senza motivo.

In pratica GASP conta sul fatto che MM *trovi* una posa idle compatibile, e sul Foot Placement per tenere i piedi fermi. Non esiste un sequenziatore che riposizioni un piede alla volta.

## Perché i tuoi piedi si alzano insieme (deduzione)

Ci sono quattro cause probabili, in ordine di sospetto:

- **Lo stato idle è una clip "raw" scelta da una riga del chooser** (`SetBlendStackFromStateName`). Quella scelta ignora la stance attuale. Il blend dalla posa finale del jab alla clip idle interpola tutte le ossa *contemporaneamente*, quindi entrambi i piedi viaggiano.
- **MM sotto il montage continua la sua idle.** All'uscita del montage "riappare" una posa che non sa nulla della stance del jab. Se il Pose History sta *prima* del Default Slot, MM non vede mai la posa del montage.
- **Offset Root Bone in Release** riporta la root al centro della capsula proprio a fine montage. Se il tuo lock non è in world space, entrambi i piedi seguono la root.
- **Curve foot speed assenti o diverse nel montage del jab.** In quel caso il Foot Placement plant/unplant si comporta in modo incoerente durante il blend out, e può sbloccare entrambi i piedi nello stesso frame.

## Cosa fare

### A. Rendere la scelta dell'idle consapevole della stance (via MM)

- Verifica che il **Pose History** sia **a valle del Default Slot**, così la query vede la posa del jab.
- All'uscita dal montage, fai tornare a `Get_MMInterruptMode` per qualche frame la modalità che forza una nuova ricerca e invalida la continuing pose (controlla il nome esatto nel dropdown **Interrupt Mode** del nodo).
- Instrada il ritorno da azione verso un database idle dedicato, invece che verso una riga raw. Mettici l'idle base più clip di correzione stance (passo sinistro, passo destro, eventualmente doppio), con peso alto sul Pose Channel (posizione dei piedi) e peso basso sulla traiettoria (sei fermo).
  - Se la stance è vicina, MM sceglie l'idle e i piedi restano dove sono.
  - Se è lontana, sceglie la clip di passo che parte da una posa simile. L'ordine "prima il piede più lontano" è implicito nei dati.
- Assicurati che anche jab e clip di passo abbiano le curve foot speed L/R (stesso anim modifier di GASP).

### B. Riposizionamento procedurale nel tuo `FGSTN_AnimNode_BlendOutFootLock`

Se vuoi restare sulle clip raw, estendi il nodo con un sequenziatore a due fasi:

```cpp
// Nel nodo: stato del replant
enum class EGSTNReplantPhase : uint8 { None, KeepPlanted, StepFirst, StepSecond, Done };

struct FGSTNFootState
{
    FVector LockedWS;   // posizione bloccata in WORLD space (immune a Offset Root Release)
    FVector StepStartWS;
    float   ErrorCm = 0.f;
    float   YawErrorDeg = 0.f;
};

// Chiamata quando il montage ha finito il blend out (peso slot ~0)
void FGSTN_AnimNode_BlendOutFootLock::BeginReplant(const FVector TargetWS[2], const float TargetYaw[2], const float LockedYaw[2])
{
    for (int32 i = 0; i < 2; ++i)
    {
        Feet[i].ErrorCm     = FVector::Dist2D(Feet[i].LockedWS, TargetWS[i]);
        Feet[i].YawErrorDeg = FMath::Abs(FMath::FindDeltaAngleDegrees(LockedYaw[i], TargetYaw[i]));
    }

    auto NeedsStep = [this](int32 i)
    {
        return Feet[i].ErrorCm > ReplantDistanceCm || Feet[i].YawErrorDeg > ReplantYawDeg;
    };

    if (!NeedsStep(0) && !NeedsStep(1))
    {
        Phase = EGSTNReplantPhase::KeepPlanted;   // resta piantato finché non parte la locomozione
        return;
    }

    FirstFoot  = (Feet[0].ErrorCm >= Feet[1].ErrorCm) ? 0 : 1;   // il più lontano per primo
    SecondFoot = 1 - FirstFoot;
    Feet[FirstFoot].StepStartWS = Feet[FirstFoot].LockedWS;
    StepAlpha = 0.f;
    Phase = EGSTNReplantPhase::StepFirst;
}

FVector FGSTN_AnimNode_BlendOutFootLock::EvalStep(const FGSTNFootState& Foot, const FVector& TargetWS, float Alpha) const
{
    const float E = FMath::InterpEaseInOut(0.f, 1.f, Alpha, 2.f);
    FVector P = FMath::Lerp(Foot.StepStartWS, TargetWS, E);
    P.Z += StepHeightCm * FMath::Sin(PI * Alpha);   // arco del passo
    return P;
}

// In Update/Evaluate: TargetWS va riletto OGNI frame dalla posa idle in ingresso (l'idle respira)
void FGSTN_AnimNode_BlendOutFootLock::TickReplant(float DeltaTime, const FVector TargetWS[2])
{
    if (Phase != EGSTNReplantPhase::StepFirst && Phase != EGSTNReplantPhase::StepSecond) return;

    const int32 Moving = (Phase == EGSTNReplantPhase::StepFirst) ? FirstFoot : SecondFoot;
    StepAlpha = FMath::Min(StepAlpha + DeltaTime / StepDuration, 1.f);
    // l'altro piede resta su LockedWS

    if (StepAlpha >= 1.f)
    {
        Feet[Moving].LockedWS = TargetWS[Moving];
        if (Phase == EGSTNReplantPhase::StepFirst)
        {
            // rivaluta il secondo piede: il bacino si è spostato dopo il primo passo
            const float Err = FVector::Dist2D(Feet[SecondFoot].LockedWS, TargetWS[SecondFoot]);
            if (Err > ReplantDistanceCm)
            {
                Feet[SecondFoot].StepStartWS = Feet[SecondFoot].LockedWS;
                StepAlpha = 0.f;
                Phase = EGSTNReplantPhase::StepSecond;
                return;
            }
        }
        Phase = EGSTNReplantPhase::Done;
    }
}
```

Note pratiche:

- **Punti di partenza da tarare:** `ReplantDistanceCm` 4-6, `ReplantYawDeg` circa 15, `StepDuration` 0.25-0.35 s, `StepHeightCm` 5-8. Lascia anche una piccola pausa tra il primo e il secondo passo.
- **In `KeepPlanted` tieni il lock finché non parte la locomozione.** La differenza di stance la assorbe il bacino (la ricalibrazione pelvis del Foot Placement, o la tua IK).
- **Il tuo nodo deve avere l'ultima parola.** Durante il replant, il Foot Placement nel layer `Procedural_Feet` non deve fare unplant per conto suo. Disattiva quel piede o porta la sua alpha a 0 durante il passo, altrimenti i due sistemi si contendono il piede.
- **Usa il lock in world space**, così Offset Root Bone in Release non trascina i piedi.
- **Mover / Network Prediction a 62.5 Hz:** fai avanzare `StepAlpha` con il delta time dell'animazione, non con il tick di simulazione. Così resta cosmetico e locale su ogni macchina.
